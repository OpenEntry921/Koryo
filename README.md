# 고려다이나믹스 기업 홈페이지 초안

Next.js App Router + TypeScript + Tailwind CSS 4 기반 정적 홈페이지입니다. 서버 API, DB, 인증, 관리자, 결제, 문의 전송 기능이 없습니다. 영문 표기는 임시이며 회사정보는 공개 전 확인해야 합니다. 현재 robots.txt는 초안 보호를 위해 전체 크롤링을 차단합니다.

## 실행 및 검증

Node.js 22 LTS 권장 (`.nvmrc`), 지원 범위 22–24. 개발환경 검증 버전은 Node 24.22.1입니다.

```sh
npm install
cp .env.example .env.local
npm run dev
npm run lint
npm run build
npm start
```

개발/정적 서버 기본 포트 3000. `npm run build`가 `out/`에 HTML, CSS, JS를 내보냅니다. `npm start`는 `serve`로 정적 파일만 제공합니다. 환경의 npm 캐시가 쓰기 불가라면 `npm install --cache /tmp/koryo-npm-cache`를 사용합니다.

## 화면 및 파일 구조

- `/`: 히어로, 회사 요약, 4개 사업 카드, 시스템 흐름, 제품 분류, 사례 예고, 문의 CTA
- `/company/`: 회사개요, 사업영역, 연혁 등록 대기, 기술 검토 분야, 위치
- `/solutions/` 및 `/solutions/[slug]/`: 6개 솔루션, 연결형 구성도, 설치 검토 절차, 기술지원 FAQ
- `/products/` 및 `/products/[slug]/`: 카테고리 필터, 대표이미지, 갤러리, 특징, 적용환경, 사양표, 연관 분류
- `/references/` 및 `/references/[slug]/`: 설치사례 목록 및 상세 템플릿
- `/contact/`: 주소·지도, 확인된 값이 있을 때만 전화·이메일 링크. 문의폼 없음
- `src/data/company.ts`: 회사 기본정보와 연락처
- `src/data/navigation.ts`: 메뉴
- `src/data/solutions.ts`: 사업 및 솔루션 설명과 흐름
- `src/data/products.ts`: 제품 타입과 제품 목록
- `src/data/projects.ts`: 설치사례 타입과 목록
- `src/components/`: 헤더, 미디어 fallback, 카드, 제품 필터, 구성도, 공통 UI
- `public/images/{products,solutions,projects,company}`: 교체 이미지 저장 경로
- `docs/verification.md`: 검증 결과와 한계

## 제품 등록·이미지 교체

화면 코드 변경 없이 `src/data/products.ts`의 배열과 `public/images/products/` 파일을 수정합니다. 정적 사이트이므로 변경 후 **재빌드가 필요**합니다. 제품의 `id`, `slug`는 고유하게 유지하며 slug는 영문 소문자와 하이픈을 권장합니다.

```ts
// Product 타입의 데이터 형식 (값은 반드시 검증된 실제 자료로 입력)
{
  id: 'unique-id',
  slug: 'unique-slug',
  category: '차량차단기',
  name: '제품명 확인 예정',
  subtitle: '모델 및 제품 설명 확인 예정',
  description: '공개 승인된 설명을 입력합니다.',
  features: ['확인된 특징을 입력합니다.'],
  specifications: [{ label: '모델명', value: '확인 예정' }],
  images: [
    { src: '/images/products/unique-slug.webp', alt: '실제 이미지의 외형과 용도를 설명' },
    { src: '/images/products/unique-slug-side.webp', alt: '제품 측면' }
  ],
  status: 'pending' // 모든 정보 확인 후에만 'verified'
}
```

현재 6개 분류는 `categories.map`으로 생성한 명시적 임시 항목입니다. 실제 등록 시 `products` 배열을 위 형식의 객체 목록으로 교체하면 됩니다. `categories`에 분류를 추가하면 필터가 자동 반영됩니다. 제품 수·이름·사진은 카드와 상세 라우트에 자동 반영됩니다. `images[0]`이 대표 이미지이고 나머지가 갤러리입니다. 이미지가 없거나 경로가 잘못되면 자체 SVG placeholder를 표시합니다. 사진에 제품명·모델명을 합성하지 마세요.

정적 배포의 Next 이미지 서버를 사용하지 않으므로 원본을 미리 최적화하세요. WebP/AVIF 권장, 대표이미지 긴 변 1200px 내외·약 200KB 이하 권장. `next/image`의 크기 예약과 지연 로딩을 사용하며, 외부 이미지 서비스 의존은 없습니다. 가능한 한 `/images/` 내부 경로만 사용하세요.

## 설치사례와 회사정보

`src/data/projects.ts`에 고유 `id`, `slug`, 현장명 `name`, 위치 `location`, 적용 솔루션 `solutions`, 이미지 `images`, 설명 `description`, 상태 `status`를 입력합니다. 실제 고객 공개 승인을 받은 경우만 `approved`로 등록합니다. 현재 `upcoming`은 실제 현장이 아닌 상세 템플릿입니다. 실제 사례 등록 시 이 임시 항목은 배열에서 제외하세요.

회사정보는 `company.ts`에서 수정합니다. `phone`, `email`은 현재 빈 문자열이며 링크를 만들지 않습니다. 공식 확인 후에만 값을 채우세요. 추후 전송 기능 도입 시 실제 수신·오류 처리 및 개인정보 수집 안내를 함께 구현해야 합니다.

## 첨부 자료 검토 및 반영 범위

첨부된 「나이스인프라 주차차단기 사업제안서-복사.pdf」(28p)를 실행환경에서 실제 다운로드하고 `pdfinfo`로 페이지 수를 확인했습니다. 스캔 PDF로 텍스트 추출 결과가 비어 있어 전체 페이지를 이미지로 렌더링해 시각적으로 확인했습니다. PDF 원본과 렌더링 파일은 저작권·출처 혼동 방지를 위해 저장소에 포함하지 않았습니다.

| 페이지 | 참고한 정보구조                                        | 홈페이지 반영                                                      |
| ------ | ------------------------------------------------------ | ------------------------------------------------------------------ |
| 1–8    | 청색 브랜드 톤, 회사개요, 조직·역량·인증 영역          | 독립적 색상·레이아웃과 회사정보 표. 타사 인증·조직·수치 제외       |
| 9–10   | 수주 표 및 설치 사진 그리드                            | 승인 사례용 그리드·상세 템플릿. 타사 고객·현장·숫자 제외           |
| 11–18  | LPR, 방문객 키오스크, 모바일 예약, 차량 흐름, 관리화면 | 6개 솔루션과 단계형 흐름, 검토 항목. 실제 공급 주장 없음           |
| 19–22  | 기술지원·사후관리, 설치 일정, FAQ                      | 일반 검토 절차와 FAQ. 타사 지원조직·일정·보장 조건 제외            |

회사정보 화면은 대화에 첨부된 이미지를 확인했습니다. 대표자, 설립일, 업종, 주소는 사용자가 제공한 내용과 대조했습니다. 회사 홈페이지 참고 URL은 공식 연락처 및 현재 공급 범위 확인 근거로 간주하지 않았습니다. 1992년 최초 창업 이력은 증빙 확인 전 비공개입니다.

## 미확인 자료 및 임시 자산

- 회사 영문명, 대표자, 설립일, 주소, 사업분야의 최신 공식 확인 필요
- 대표 전화·이메일·공식 로고 원본 미확인. 헤더는 임시 텍스트 워드마크
- 제품 6개 분류 전체: 제품명·모델·특징·적용환경·사양·실제 공급 여부 확인 예정
- 설치사례 1개: `upcoming` 등록 예정 템플릿, 실제 실적 없음
- 메인 SVG는 자체 작성한 주차장 구성 개념도, 모든 placeholder도 자체 SVG/CSS
- 사원수, 매출, 특허, 인증, 수주실적, 고객사, 후기는 게시하지 않음
- 폰트는 `@fontsource/noto-sans-kr`의 Noto Sans KR을 자체 호스팅하며 패키지에 포함된 SIL OFL 라이선스 적용

## Cloudtype 배포 (수동)

자동 배포나 배포 설정 파일을 생성하지 않았습니다. PR 검토·수동 병합 및 실제 정보 확인 후 진행합니다.

1. Cloudtype에서 GitHub 저장소를 연결하고 검토된 브랜치를 선택합니다.
2. Node.js 22 서비스 유형을 선택합니다. 의존성 설치는 `npm ci`, 빌드는 `npm run build`로 설정합니다. 설치와 빌드 입력란이 하나인 경우 `npm ci && npm run build`를 입력합니다.
3. 실행 명령은 `npm start`, 서비스 포트는 `3000`으로 설정합니다. 런타임 `PORT`가 지정되면 시작 스크립트가 해당 포트를 사용하므로 서비스 포트와 일치시킵니다.
4. 빌드 환경변수 `NEXT_PUBLIC_SITE_URL`에 실제 HTTPS 도메인을 설정합니다. 이 값은 메타데이터와 sitemap에 빌드 시 반영되며 비밀값이 아닙니다. 변경 후 재빌드하세요.
5. 실제 정보 검토 후 `src/app/robots.ts`의 `disallow: '/'`를 `allow: '/'`로 변경하고 재빌드합니다. robots는 접근통제 기능이 아닙니다.
6. 배포 후 상세 URL 직접 진입, 모바일 메뉴, 이미지, 지도 링크, sitemap과 OG 미리보기를 점검합니다. 서비스 자동 배포 토글은 활성화하지 마세요.

정적 웹 호스팅도 `out/` 디렉터리를 배포하면 가능합니다. 이 경우 디렉터리별 `index.html`과 `404.html`을 호스트 규칙에 맞게 제공하세요. 서버 런타임이 필요하다면 위 정적 파일 서버만 사용하며 Next API 서버나 DB는 필요하지 않습니다.

## 브랜치·PR 주의사항

시작 시 저장소는 커밋이 없는 빈 저장소였고 `git ls-remote origin`에 ref가 없었습니다. 로컬 `main`은 unborn 상태였습니다. 따라서 `main`의 기존 이력에서 분기하는 것은 불가능하여 지정 작업 브랜치에서 최초 커밋을 작성합니다. 사용자 지침에 따라 `main`에는 직접 커밋·push하지 않습니다.

GitHub PR은 유효한 base 커밋이 필요합니다. 원격 `main`이 없는 상태에서는 PR 생성이 거부될 수 있습니다. 그런 경우 작업 브랜치만 push하고 오류를 보고합니다. 저장소 관리자가 기준 브랜치 초기화 방침을 정한 뒤, 필요하면 공통 이력을 갖도록 작업 브랜치를 재구성하여 수동 병합용 PR을 생성해야 합니다. main을 임의 생성하거나 자동 병합하지 않습니다.
